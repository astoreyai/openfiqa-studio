# Security review

**Scope:** OpenFIQA Studio as it stands at the commit containing this file. Reviewed 2026-08-08.

This is an internal review, not an external audit. Nobody outside this repository has examined the
code. Where a control is untested, it says so — a security document listing controls nobody has
pushed on is a description, not a review.

---

## Threat model in one paragraph

The studio runs untrusted-ish scientific code against biometric imagery on a researcher's machine,
and can export artifacts that leave it. The three things that would actually hurt are: a biometric
sample reaching a public artifact, arbitrary code executing because a filename or a workflow field
was interpreted rather than passed, and a result being published that nobody can re-derive. The
controls below map to those three.

## Controls, and how each is verified

| Control | Mechanism | Verified by |
|---|---|---|
| No shell interpretation of arguments | `RunSpec.argv` is a list; `asyncio.create_subprocess_exec`, never `_shell`. The API exposes no `shell`/`command`/`cmd` field | `test_shell_metacharacters_in_arguments_are_not_interpreted` runs a hostile argument against a canary file; `test_run_api_offers_no_shell_string_field` reads the OpenAPI schema |
| Biometric imagery never enters the repository | `.gitignore` blocks image extensions; only the app icon is excepted | `test_no_biometric_image_is_tracked_by_git` checks git's **index**, not the working tree — the tree is what `.gitignore` protects, the index is what ships. Also enforced in CI |
| Restricted samples never enter a public export | `classification` is required with no default; `public_export_is_safe` is default-deny | `test_public_export_refuses_restricted_samples` |
| Machine-local engine paths stay local | `config/local-paths.yaml` is gitignored; an example file is committed instead | `test_no_local_machine_paths_are_tracked`, plus a CI job |
| Supplied environment never reaches logs or run records | Run events carry only what the child wrote to stdout/stderr | `test_run_events_do_not_echo_the_process_environment`, `test_run_records_do_not_persist_the_supplied_env` |
| Engine stderr is bounded in HTTP responses | `exc.stderr[-2000:]` | `test_adapter_error_detail_is_truncated` |
| Blocked engines cannot execute | Both routes call `PluginRegistry.assert_executable`; neither is the soft one | `test_blocked_plugins_cannot_be_executed_through_any_route` |
| An invalid plugin manifest stops the registry | Every manifest is schema-validated at load | `test_registry_refuses_to_serve_an_invalid_manifest` |
| Checkpoints cannot execute code | `torch.load(..., weights_only=True)` | reviewed; not adversarially tested — see limitations |
| CORS is an allowlist | Explicit origins, `allow_credentials=False`, never `*` | `test_cors_is_an_allowlist_not_a_wildcard`, `test_unknown_origin_is_not_allowed` |
| The studio works offline | No outbound call on any request path | `test_the_control_plane_serves_with_no_outbound_network` blocks `socket.socket` and exercises health, plugins and project creation |
| Supply chain is enumerable | SBOM generated by reading the installed environment, not a lockfile | `test_sbom_is_generated_from_the_installed_environment`; 42/42 Python components report a licence |

## What the SBOM covers that a pip listing would not

`ofiqpy` is MIT, and it loads `ofiq_config.jaxn` and every model weight from an **OFIQ-Project**
checkout under BSI terms (B-P01-09). An SBOM listing only pip packages would miss that entirely, so
external engines are enumerated separately with their supplying commits.

## Known limitations

- **No external audit.** S15 in the build plan is not done.
- **`weights_only=True` is reviewed, not attacked.** No malicious checkpoint has been constructed to
  test the boundary.
- **No static analysis or dependency-vulnerability scanning yet.** The CI supply-chain job generates
  an SBOM and enforces the data-boundary rules; it does not run a CVE check.
- **Desktop shell unverified at runtime.** The Tauri binary compiles and links, but no window has
  been opened — B-P03-01. Nothing about its runtime behaviour has been observed, including whether
  it enforces the CSP declared in `tauri.conf.json`.
- **CI cannot exercise the engines.** A runner has no ofiqpy checkout, no weights and no corpus, so
  those tests skip. Engine coverage exists only on a configured workstation.
- **One unexplained test flake.** `test_reproduction_of_a_deterministic_workflow_is_exact` failed
  once in a full-suite run on 2026-08-08 and passed alone, as a module, and on subsequent full runs.
  Diagnostics were added; the cause is not known.
